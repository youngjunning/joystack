# tstack 方法局部融合方案

日期：2026-11-23。状态：Skill 契约融合完成；验证与独立评审已通过，Git 交付分别回读。方案原文留本仓库。

在[完整评估](../research/2026-11-23-tstack-assessment.md)之后选择补强已有能力，不新增总控流程。采用 tstack `11e37a74d0a6868c121cd0910ab2b3bd9873b92a` 的语义重审、接手贡献、PR/评论、单一观察者、等待预算与 diff-growth。版本和许可见[融合记录](../../skills/engineering/joy-stack/references/tstack-integration.md)。

## 最小实施

1. Continue/Understand：旧目标与最新纠正、当前价值、处置建议、继承/新增贡献。
2. Loop/Review：checkpoint、时间/轮次预算、终止确认；多视角可选、不默认额外模型调用。
3. Git：PR/MR 终点、描述/评论回执、贡献、消息与当前 gate 分离。
4. catalog、README、共享契约与十二个静态案例；保持来源/许可与各宿主降级。

专用领域扩展可映射同一语义，平台数据与命令留所属目标，不进入公开核心。没有新增运行时、帐号、服务、force push、自动合并或平台资源写权限。

## 验收与后续

可验：references 可发现、职责无冲突、来源保留、静态案例、原有脚本回归和独立评审。结构检查只证明协议未丢，不证明 Agent 真实任务必然触发或成功。

未实施：可执行 watcher、三供应商 Council、真实 PR/MR 生命周期与权限写入、实际模型成本/挂起恢复。它们只在另行获准任务内验收，不因融合自动成为本轮必做事项。

## 已取得证据

1. 公共仓库根目录测试 18 项通过，其中本次新增 6 项静态契约检查；初始缺少规则时新增检查失败，补齐后通过。一个相对路径断言按实际 reference 位置修正，没有改变行为门禁。
2. 现有 worktree 脚本 53 项回归通过，仓库模块/catalog/独立安装引用/公开边界校验通过。
3. 第 1 轮独立只读 Review 已 APPROVE，无开放 blocker/should；复验新增 6 项检查与 validator。评审只覆盖 Skill 契约、文档、测试，不代表真实平台运行验收。
4. 实际改动没有复制上游 watcher、添加模型调用、改变平台授权或创建/合并真实 PR/MR。既有 LICENSE/NOTICE 保留。

后续仅在获准真实任务上做行为与成本验收；缺少运行结果不能称为普遍质量提升，本次没有这项外部任务承诺。
