# JoyStack · Debug

先建立可重复的失败事实：期望与实际、最小条件、频率、环境和可观察证据。然后把问题缩小到具体边界，为每个假设设计一个能推翻它的观察或实验。

不要把偶然消失、一次重试成功或日志里最醒目的错误当作根因。先修导致失效的机制，再用最贴近根因的回归保护确认；如果只能降低概率，要如实说明残余条件与监控/恢复路径。

当根因表明需求或系统边界本身有误，回到 [`joy-shape`](../joy-shape/SKILL.md)；修复完成后交给 [`joy-verify`](../joy-verify/SKILL.md)。共享交接标准见[套件契约](../joy-stack/references/stack-contract.md)。
