# JoyStack 全局目录

JoyStack 持久运行数据默认放在当前运行环境解析出的用户家目录下的 `.joystack`。脚本通过 `Path.home()` 解析家目录；遵循当前环境的 home 信息，不写死账号或宿主路径，不从 cwd、仓库路径或工作区反推家目录。下文 `~` 只表示这个环境家目录。

`JOYSTACK_HOME` 是明确的 JoyStack 数据目录覆盖，不会修改或重新定义家目录。只有平台配置、用户明确指定或隔离测试时使用。模块按用途使用子目录，不各自在宿主配置目录里创建一套状态。

当前落地结构：

```text
~/.joystack/
├── worktrees/
│   └── <repo>-<repository-id>/
│       └── <task-slug>/          # 自建 Git worktree
└── state/
    ├── worktrees.json           # 任务用途、会话、状态、目标和保留条件
    └── worktrees.json.lock      # 并发写入锁，不表示任务仍在运行
```

- Skills 源码和发现入口继续遵循用户已有安装约定；这个目录存运行数据，不复制一套 Skills 或配置宿主。
- 平台重排安装目录时，从当前已发现 Skill 的实际位置加载模块正文与配套引用；相对链接按该 Skill 文件所在目录解析。缺模块就报告缺项，不按本机账号路径猜文件、不另建副本或擅自安装。
- `joy-git` 负责 worktree 台账和生命周期；详细操作见 [worktree 生命周期](../../joy-git/references/worktrees.md)。其他模块调用同一入口，不建立另一份 worktree 清单。
- `init` 是显式初始化动作：创建当前需要的目录和空台账，保留已有记录；普通查询和创建计划不初始化目录。不预建未实现的日志、缓存或服务目录。
- 已有散落或宿主管理的 worktree 先盘点、确认用途后登记原路径。统一根目录约束新的自建目录，不授权搬迁旧目录；宿主支持指定位置时优先配置到这个根目录，不支持时保留宿主路径并统一登记。
- 台账只存本机必要任务信息，不纳入项目源码、公开 Git 或内容索引；不能用文件锁、目录年龄、提交时间推断会话活跃。读写失败保留现场，不重置记录。

以后模块确有持久运行数据时，也使用这个根目录并说明目录用途、恢复和清理条件；独立产品的用户数据仍归其产品，不因为使用 JoyStack 就迁移过来。

## 受限平台

平台只允许当前工作区读写时，由调用层读取平台明确给出的边界，设置 `JOYSTACK_WORKSPACE`，或在脚本子命令前传 `--workspace`。边界不是家目录，不因设置边界自动改 JoyStack 位置：

- 环境家目录在允许区域内：仍使用该家目录下 `.joystack`。
- 环境家目录不在允许区域内：停止目录写入并报告不兼容；只有平台或用户明确给出覆盖位置时设置 `JOYSTACK_HOME`，不静默搬到 cwd、不自行改 HOME。
- 在执行 Git 或创建/登记之前校验真实路径：当前 cwd、JoyStack home、台账和锁文件、worktree 根目录/目标目录、Git directory/common-dir 均须在指定工作区内；创建分支也检查实际 ref 与 reflog 路径。`--index`、`--root` 和已存在的符号链接不豁免检查；linked worktree 在内但其 common-dir 在外时也拒绝。
- 盘点可显示 Git 提供的工作区外目录条目，但不读取其状态或进入目录；标为边界阻塞。台账有越界路径或仓库读取失败时明确报告，不当作空列表，不重置旧记录。
- 测试在 `JOYSTACK_WORKSPACE` 设置时使用工作区内的临时目录；未设置时才使用系统临时目录。夹具清除继承的 Git 路径重定向，并限定虚拟仓库发现范围；拒绝测试仅向产品子进程显式注入重定向。运行测试也遵守平台授权，不因为这是测试而访问外部用户数据。

调用示例（变量由平台确认，不自行把任意 cwd 认定为授权边界）：

```bash
python3 "$SKILL_DIR/scripts/worktrees.py" --workspace "$JOYSTACK_WORKSPACE" list --repo "$REPOSITORY" --json
```

这些检查是操作前校验，不是安全沙箱；原生 Git 的 hooks、filters、fsmonitor 或并发路径变化仍可能带来外部副作用，必须由平台执行权限/沙箱约束。调用层在权限不能证明满足时只读或停止，不用脚本参数绕过平台。提交、推送、合并、删除与安装各自需要已有授权；安装 JoyStack 不自动授予它们，模块中的自动交付仅在平台允许且项目授权满足时适用。
