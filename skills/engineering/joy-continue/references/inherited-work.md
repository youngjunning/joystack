# 继承工作：语义重审与接手契约

在继续旧分支、接手他人的 PR/工作区/Agent 任务或恢复中断任务时读取。先只读确认事实，再决定是否执行；原方案与交接摘要是定位线索，不是通过证据。

## 先核对当前目标

恢复用户原目标、最新纠正、取消或暂缓决定；明确源仓库与 PR/任务、base/head、未提交改动、已有验证、下一步和现有负责人。缺失历史或对象不唯一时说明缺口，继续无歧义的只读核对，不从分支名或旧摘要推断授权。背景问题不会自动取消先前目标，明确取消则不自动恢复。

由 `joy-understand` 查当前实现与基线变化：问题是否已被解决，API/类型/状态所有者是否变化，合入会否恢复主动删除的旧行为，维护成本是否仍值得。只读重审先于机械 rebase，按事实给出一种处置：

| 处置 | 判定 | 下一步 |
| --- | --- | --- |
| KEEP | 目标仍有效，原实现仍合适 | 按项目规则继续最小实现/验证/交付 |
| REWORK | 目标仍有效，但原实现与当前契约冲突 | 交 `joy-shape` 收敛必要重做范围，再依据现有授权实施 |
| SUPERSEDED | 已被替代、目标已取消或收益不再成立 | 给出证据和停止建议；关闭 PR、删分支仍独立核对授权 |
| UNRESOLVED | 目标、所有权、当前状态或来源不足 | 列最小待查事实与恢复条件，不制造“已过期”或“可合入”结论 |

年龄和沉没成本不能独立决定处置。已授权的同目标工作正常推进；只有范围、外部影响或不可逆性发生实质改变才请求新决定，不把 REWORK 一律变成等用户。

## 接手后保留责任与贡献

明确继承内容、原作者/共同作者、接手人的新增修正、验收负责人及交付终点。保留原 commits 的作者和已有 `Co-authored-by`；新修正单独可追溯。squash 可能丢失贡献信息时，在获准的 PR/合并提交中按已核验身份保留，不猜邮箱，不把模型署名当人类贡献。

默认沿用当前获准 checkout 与交付路径；脏现场或历史不能安全拆分时交 `joy-git` 隔离。接手不是自动替换 PR、关闭原 PR、改目标分支、force push 或自称原作者。工作期间来源又前进时重新核对差异与所有权，避免两个执行者独立交付同一目标。

确需重放 commits 时，交 `joy-git` 遵循历史与分支授权；用 `git range-diff` 和最终行为 diff 对照重放前后，核验原意未丢、新基线不变量未被撤回。冲突揭示产品/架构分歧时返回处置判断。允许自动 fast-forward 的交付不因此变成共享分支 rebase/force push 授权。

## 可交接的完成条件

输出处置、来源与当前 head/base、继承/新增贡献、已验证结果、下一步和终点；真实工作及新修正依 `joy-verify` 取得相称证据。原作者的 green、旧评审与交接“完成”不能批准当前 diff；未执行的验收明确标待验证。完整方案保留在所属项目，续接只引用必要状态。

方法来源：tstack `modernize`、`takeover` 的语义重审与归属原则；来源和版本见 `joy-stack` 的 `references/tstack-integration.md`（按 Skill 名发现，路径从其实际安装目录解析）。本文件独立表述，不绑定某个 PR 平台或专有会话运行时。
