# 目标环境测试

目标环境测试验证低层测试无法覆盖的运行时、协议和人机交互边界。先确认目标风险，再选择实际需要的浏览器、设备、服务、账号角色或辅助技术组合；未执行的组合明确列出，不用自动检查冒充真实环境。

## 浏览器与 E2E

先识别静态页面还是需要服务端、构建或异步数据的动态应用。沿用项目的启动命令并保护用户已有进程；等待应用可用后先观察真实渲染态、可访问树、控制台和网络，再选择交互与断言。动态内容使用框架的条件等待或 web-first assertion，不用固定 sleep 猜时序。

E2E 只保护关键用户旅程与真实集成边界。规则穷举和纯数据边界留在更低层；每个场景独立准备与清理状态，避免依赖执行顺序。定位器优先使用用户可感知的 role、name、label 和稳定语义；产品明确提供的测试标识可作为后备，不依赖易变 DOM 层级和样式。

失败时保留能定位问题的 trace、截图、视频、控制台、网络或分步状态，但只收集任务必要内容并避开凭据与无关隐私。页面最终可见不证明中间错误不存在；按风险检查错误提示、恢复路径、重复提交、刷新与返回等状态。

## 辅助技术

自动 accessibility 检查适合发现确定性规则问题，不能替代屏幕阅读器与键盘的真实交互。按产品支持范围选择平台与辅助技术矩阵，检查 browse/focus 模式、朗读名称与状态、键盘顺序、焦点进入与恢复、动态公告、验证错误和弹层退出。

报告必须区分自动规则通过、浏览器键盘验收和真实屏幕阅读器验收。没有目标平台或人工能力时，保留为待验证，不根据 DOM 或 ARIA 静态结构推断用户体验已通过。

## API 契约

先从路由、OpenAPI、调用方和实现盘点 endpoint、method、schema、认证授权、状态码、幂等与实际支持的分页、上传、限流等能力，再形成风险驱动的契约矩阵。每个接口按需覆盖：

1. 有代表性的成功响应及持久化或副作用；
2. 未认证、无权限和资源归属边界；
3. 缺失、非法、边界和冲突输入；
4. 错误状态、错误结构与不泄漏敏感数据；
5. 只有契约存在时才测分页、排序、重试、幂等、上传和限流。

断言同时核对 HTTP 语义、响应结构、关键字段和业务结果。不要从当前实现机械生成笛卡尔用例，也不要把 mock server 自己定义的响应当作生产兼容证据；需要真实边界时使用隔离测试服务或契约双方可回放的样本。
