# JoyStack · Token Efficiency

以完成同一目标所需的总 Token 为优化对象，不把短回复、低延迟或缓存命中冒充总量下降。按技能名使用当前宿主已发现的能力；本模块提供执行约束，不接管领域判断或建立常驻优化器。

## 进入、输出与交接

用户要求省 Token、降调用成本，或任务将加载大量资料、反复调用工具、跨轮恢复时进入。在 JoyStack 工程任务中默认应用下列轻量策略；明确的一行答案无需为了优化再加载完整套件。通用策略不绑定模型系列、供应商、云端/本地部署或宿主；保持用户指定的模型及其有效设置，不默认改模型、代理、账户、额度或宿主配置。

输入是当前目标、有效约束、可用工具与已有证据；输出是采用的最小执行路径、可复用的证据定位和仍需补证的边界。有可比 usage 才附测量结果；普通任务不新增省 Token 报表、台账或计量调用。

## 全程策略

1. **先定位，再加载。** 复用本轮已读且仍有效的约定与事实；按名称、路径、符号或错误先搜候选，再读相关片段与调用上下游。Skill 只加载实际主导模块和当前分支的 references；代码、配置或并行状态变化后刷新受影响证据。
2. **筛选在工具侧完成。** 大文件、API、日志、表格和检索结果先取字段、范围与相关行；长输出保留退出码、错误、统计、覆盖/分页状态和完整证据的位置。截断或缺页不代表无命中；答案依赖缺失部分时续读，不反复扩大整份输出。
3. **确定性工作交给工具。** 查询、聚合、去重、格式转换和校验用已有 CLI/脚本；批量处理同一来源的独立请求。一次调用能安全得到所需事实时，不再逐项问模型；并行缩短等待，不自动减少 Token。
4. **控制规划与协作。** 小改直接执行，复杂任务只维护一份当前计划与 finding ledger。已有授权允许委托时只交接有界目标、必要工件、约束、证据和停止条件；不复制整段会话、不重复同一工作。必须独立评审的任务仍保留原门禁。
5. **给重试与验证边界。** 同一失败先处理触发原因再重试；等待采用宿主的 wait 或有界退避。沿项目要求跑受影响验证，结果相同且基线未变时复用证据；修改相关代码或验收环境后重验。预算不足保留未完成项，不能把省 Token 当作通过。
6. **压缩表达，不压缩证据。** 回复按用户需求保留结论、必要解释、风险与下一步，去掉重复复述和无信息进度。用户要求详解或项目要求报告时照常满足；长工件只在获准目标保存，聊天给结果和定位，不把同一全文再贴一遍。
7. **续接只带有效状态。** 交给 joy-continue 保留目标、最新纠正、成果位置/版本、证据、未知项和下一步；原始记录仍可回查。稳定偏好与运行状态分离，按现有记忆授权处理；本模块不自动扫描历史或写长期记忆。
8. **按实际能力选择优化。** 复用已有配置、工具契约和响应判断缓存、会话续接、推理控制、输出上限及 usage 能力，不按模型名称猜参数。通用策略照常执行；能力未暴露或不支持时跳过对应优化并保留未知项，不额外探测或伪造支持。宿主控制的请求与历史不由 Skill 擅自改写；缓存不等于上下文变短，短回复不证明总生成或推理 Token 同比例下降。

发现具体瓶颈时，仅阅读 [分场景操作](references/optimization.md) 对应部分。需要落实会话、缓存、模型设置或计费优化时，再从 [来源与能力适配](references/sources.md) 选择当前接口的官方资料；已知供应商只是案例，未知供应商不影响通用策略，不跨接口搬用参数、阈值或节省比例。

## 成功条件与停止

必要权限、输出格式、验证与来源完整性不因优化降级；过度裁剪导致理解缺口、无效重试或漏验时立即放宽相关上下文。优先减少重复推理和返工，而不是最低单次输入。

有真实 usage 时依当前接口定义区分输入、缓存、输出及推理明细，核对各项包含/独立关系后统计，缺项记未知；按同任务、模型、设置、质量门槛和计费口径比较。没有匹配基线或宿主不提供计量时，只报告实际采用的策略与测量缺项，不声称节省百分比或付费额度下降。

本模块的路由与边界可按 [行为检查](references/behavior-checks.md) 演练；文件校验、工具演练和真实模型用量验收是不同证据。具体任务完成后回到原主导模块；代码交付与缓存/API 配置变更仍遵从各自项目规则。
