# 分场景操作

只读当前瓶颈对应的部分。已有宿主工具能完成筛选时优先使用，不另建 Token runtime；下面命令是示例，不是必须流程。

## 资料与代码

- 已有准确路径或调用点时直接定位；未知时先搜索目录/文件名和符号。只扩展会改变下一步判断的依赖，避免整个仓库、Skills 库、锁文件或历史会话进入上下文。
- `rg --files -g '*upload*' src` 找候选，`rg -n -C 3 'handleUpload' src/api` 找调用，再用 `sed -n '80,150p' src/api/upload.ts` 读取相关区域。搜索范围和词项不确定时扩大一次或换线索，不能把窄搜空结果当成不存在。
- 已读文件未变且覆盖当前问题时复用；补丁改变接口、并行编辑、工具返回版本变化或摘要覆盖不足时重新读取相关片段。带行号、hash、commit 或查询时点的定位比再次贴整份原文更可用。
- 必须读取的项目协议不跳过；稳定约定维持单一来源，动态进度与执行日志不填入每轮常驻的 AGENTS.md 或 Skill 描述。

## 工具、日志与工件

- API 先选择当前问题需要的字段；数据库先依 schema 和权限做查询再在服务端聚合，明确查询范围。保留完整性标志、游标和总量含义；要求全量结论时完成必要分页。
- 长命令把完整 stdout/stderr 写入任务允许的日志位置，直接保存原命令退出码，再返回状态、失败摘要和证据路径。例如 `task_command > "$log" 2>&1; command_status=$?`，筛选后仍报告 `command_status`，不要把 `grep`/`tail` 的成功当原命令成功。启用 errexit 的脚本用条件分支接住失败后再保存退出码；避免把凭据或无关私密内容写日志。
- 对日志先筛错误和对应上下文，再按时间/请求 ID 续读；不要只看最后几十行就宣布通过。输出工具发生截断时从已保存结果定向续读；没有完整副本时重新查询缺失区域，而不是假装已经读取。
- 大补丁直接写入获准文件，再用摘要和差异定位交付；输出必须完整的 JSON、代码或合同正文时保留完整性。不得靠强制长度上限截断机器可读结果。
- 图像/PDF/视频按任务选相关页、区域或时间段，优先文字/元数据定位；视觉判断需要原图或跨页关系时保留足够分辨率与上下文。多模态大小和字数不是通用 Token 计数器。

## 调用、规划与质量

- 合并同一阶段的独立检索，避免“先调用取 ID、再逐项取摘要、再逐项取同样字段”；有依赖、同一对象写入或接口顺序约束时保持串行。
- 只维护一份可变的任务状态；进度只更新新发现、阻塞或重要阶段，不反复讲计划。避免以优化为由加入审计会、额外模型复核或每一步 usage 检查。
- 任务已有独立评审要求时继续执行；授权允许的 sidecar 应有不重叠范围，传最小原始证据而非作者预设结论。子 Agent 的输入/输出和计费都计入总量；不能把父会话变短当总成本下降。
- 先跑项目指定的局部验证，再按风险扩大。基线变更、不可知影响或项目要求全量时跑完整检查；降低重跑次数靠可比证据，不靠取消测试。
- 重试先识别临时错误、参数错误或授权失败；已有不可重试/外部写入规则优先，结果未知先回查实际状态。Token 预算和重试预算不是新权限。

## GPT Sol 与宿主/API

- 用户指定 Sol 时保留实际 model/provider 路由。展示名、内部别名或代理名称不足以确定公开 API model ID、价目表、缓存能力或上下文窗口；不凭名字补写配置。
- 降低输出冗余和重复取证先于降低推理；`reasoning`、verbosity、输出上限或模型切换只在用户允许且当前接口支持时评估。短回复约束不控制隐藏推理的实际消耗。
- 自有 API 的稳定开发者指令、示例和工具定义可形成前缀；保持此前消息及工具结果身份/顺序，追加新证据和消息。模型升级后核对顶层 instructions 的插入位置和缓存资格，不能默认所有“系统提示词在前”都符合当前请求序列。
- 中途改写早期历史或降级模型可能丢失推理上下文并增加重复工作，按官方指南与质量用例验证；缓存保持不得阻止必要纠正或安全更新。
- 继续会话、缓存保留、compaction 与请求字段由当前宿主/接口决定。只有用户要求接入或配置优化时才修改实现；Skill 文本不保证改变后台请求、计费或套餐额度。

## 测量与续接

- 复用宿主已提供的 usage，不默认扫描全机会话/日志。比较相同目标、质量门槛、模型、设置、窗口、缓存状态与总调用范围；计入重试、工具回传、子 Agent 和最终工件。
- 输入、缓存读取/写入、输出分别展示；reasoning 明细按 provider 说明处理，若已包含在输出中不再重复相加。usage 缺失记未知，不填零。
- 缓存命中比例与真实总 Token 节省、账单变化、耗时分别计算；缓存写入可能有额外费率，当前模型的计费字段和价目表优先。只有一组结果时记观察，不称优化前后对比。
- 没有官方 Tokenizer 或 usage 时，字节、字符、行数只作为工件体积代理，明确标签；不能伪装成 Token 或将延迟反推缓存。
- 压缩上下文前由 joy-continue 保存工程续接定位和关键未知项，仍按宿主允许方式处理；不擅自写永久记忆、不复制整段会话、不强制另开会话或改压缩阈值。
