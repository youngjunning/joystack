# 平台观察：只提供事件，不做合并决定

这是宿主中立协议，没有实现新的 watcher、后台服务或平台 API。先核对现有工具能否取得当前 head、检查/评审的版本归属、分页完整性和终态，再在授权与预算内使用有界等待/通知。缺少能力时降级为只读回查和可续接交接，不造命令或重复轮询器。

## 单一所有者与恢复

每项 PR/MR 的等待由单一所有者负责；reviewer 子任务不另外监听。接手前查已有观察器、任务绑定和运行状态，不依赖 PID 年龄判空闲。必要持久化沿用当前环境 JoyStack 全局目录与权限；只存变更身份、owner、head/base、cursor、已处理事件、观察时间、预算和停止原因，不存评论全文、源代码、凭据或无关资料。

重启先核对已有观察任务与剩余预算，再从确认 cursor 续读。游标过期、存储失败或分页截断时标完整性不足，重建已说明的基线；这是有损恢复，不承诺无遗漏。事件按平台稳定 ID/版本去重；评论编辑不能自动视为旧问题已处理，必要时查最新正文。

## 最小观察记录

| 字段 | 含义 |
| --- | --- |
| target、owner | 仓库/变更、观察任务；对象不唯一时不开始 |
| head、base、observed_at | 当前版本与时间；多次调用不假设原子快照 |
| kind、evidence | 检查、评审、冲突、关闭/合并等事件与真实引用 |
| completeness、cursor | 完整/partial/UNKNOWN 与返回游标；空列表不是完整证明 |
| state、reason、remaining_budget | 等待/不可用/终态、原因、剩余预算 |

字段无法读取时记 UNKNOWN，不伪造；本表是证据记录，不要求平台 API 原样提供这些字段。

## 处理与退出

1. 无变化时正常等待，不刷“仍在等待”。事件到达后父任务核实；真实 finding 交 Review/Build/Verify，仅 status event 不自动改代码。
2. head/base 变化使旧 checks/review/ready 候选失效；重新读取同版本证据。多次读取也不等于消除竞态。
3. green/ready/exit 0 不是合并许可。保护规则不可读、人工阻断、部分分页、旧 checks 或机器人完成但失败，回到 UNKNOWN/blocked。真实门禁由本模块的[变更交付契约](pr-delivery.md)与平台规则负责。
4. 等待必须有任务总时间/调用预算。沿用已有预算；未指定时先说明相称的有限预算，不以换观察器/重试重置。rate limit/网络失败按平台恢复条件有限等待，不切换未授权身份。
5. required gate 满足只交父任务核查；merged/closed、用户停止、预算耗尽、能力不可读或交接时解除本任务订阅并确认停止。无法确认则保留 owner/handle 与恢复条件，不虚报停止或杀掉他人任务。

只读观察不产生提交、推送、触发评审、评论、resolve、合并或发布授权。没有观察适配器时，其它基础模块和获准直接 Git 交付照常运行。
