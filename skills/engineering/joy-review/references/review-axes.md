# 规格与规范双轴评审

用于分支、PR、工作区 diff 的源码审查；输入是任务授权范围、可重现的比较基线、原目标和项目规范。两个问题分别回答：实现是否满足约定结果（Spec），实现是否符合项目契约与工程标准（Standards）。不是把一个综合评分拆成两栏。

## 固定审查对象

1. 先核对 checkout、HEAD、用户给出的 ref、暂存/未暂存/未跟踪状态与比较意图。分支 review 可以使用已解析 ref 的 merge-base 比较；用户要求审当前工作区时必须包含对应 diff 与新文件，不用仅提交历史遗漏现场。
2. 用 `git rev-parse --verify <ref>^{commit}` 或宿主等价能力确认引用，记录实际 SHA、比较命令、文件列表和目标范围。无效 ref、空 diff 或取不到源对象先报告，不能让 reviewer 猜另一个基线。明确工作区 diff 不需要为了形式强迫用户再给一个 ref。
3. 审查开始后以这些字节为固定输入。作者改动使基线变化时，返回原 Loop 更新证据；不能一边审旧文件一边宣称新 diff 已通过。

## 找原目标与规范

Spec 来源按证据查找：用户明示的验收/规格与最新纠正 → 当前项目 tracker 协议对应的工作项及提交引用 → 任务相关的规格/方案文件 → 仍缺少时询问最小待定信息。URL、编号、文件名只用于定位，读取正文后才引用；按项目事实处理来源冲突，不伪造 tracker 或自动安装旧套件。

规格缺失时，列出已知约定和无法判断的部分，不能声称 Spec 通过；已能做的 Standards 审查继续。反过来，代码符合需求也不能抵消不兼容、安全或既有标准的失败。

Standards 先读受影响目录的 AGENTS、贡献指南、规范、协议和测试约定。项目明确规则优先，已经由可信工具强制检查的格式问题不重复当作人工 finding。没有规范时按现有契约和下面的启发式检查，不编造“违反项目标准”。

## 维护性启发式

以下 Fowler code smells 是寻找风险的词汇，不是自动阻断规则，也不是要求做全部重构。只在当前 diff 有可解释影响时给出位置、现象、后果和合适修正；项目有意选择或没有风险证据时不扣分。

| 线索 | 核对的实际问题 |
| --- | --- |
| Mysterious Name | 命名是否遮住调用者需要理解的职责或业务含义 |
| Duplicated Code | 相同决策是否散落，导致修复不能保持一致 |
| Feature Envy | 操作是否长期依赖另一对象的内部数据，所有权是否放错 |
| Data Clumps | 总是共同出现的字段是否表达一个真实概念而非偶然组合 |
| Primitive Obsession | 字符串或数字是否丢失关键领域约束 |
| Repeated Switches | 相同类别分派是否重复并出现差异，是否可集中而非堆抽象 |
| Shotgun Surgery | 一个行为变化是否迫使多个无关位置同步修改 |
| Divergent Change | 同一模块是否为多种独立原因频繁变化 |
| Speculative Generality | 扩展点、参数或层次是否没有当前需求和调用证据 |
| Message Chains | 调用方是否了解不该暴露的内部导航链 |
| Middle Man | 转发层是否保留了实际策略/隔离契约，还是只增加调用负担 |
| Refused Bequest | 实现是否拒绝继承契约，使用组合是否更诚实 |

设计 seam 或调整模块职责时，按名称加载 joy-shape 的模块设计分支；测试保护质量交 joy-test，不因为重构删除已有保护。

## 分轴结果与独立性

每轴独立列 finding、证据、覆盖范围和结论，整体通过要求必要的两轴均有依据且 blocker/should 已解决。可把同一事实归入主要轴并引用另一轴，但不能用规范通过掩盖规格失败，也不能让合并排序丢失任一轴结论。偏好和 smell 都要与硬契约违规区分。

不自动启动两个 reviewer。需要独立上下文或多视角时先核对当前宿主和用户是否允许 delegation、所需模型及预算；允许时给每个 reviewer 同一基线、自己的问题、完整必要规范/规格和只读范围，不重复分派。缺少授权/工具时由本任务分轴检查并明确独立评审未执行，不能自报等价。

本分支只返回评审证据；finding ledger、作者修正、复验与终态仍由原 joy-loop 负责，不重开循环、扩大范围或重置预算。
