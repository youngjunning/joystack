# JoyStack · Govern

跨技能交接按名称使用当前宿主已发现的 Skill，不要求相邻安装目录；缺少所需能力时报告缺项，不猜路径或擅自安装。

先做只读体检，再提出治理动作。采集常驻文档与链接、实际测试入口和 CI 调用、近期活跃代码、分支/upstream、worktree、脏状态与合入证据；脚本或命令只负责客观事实，是否过期、重复、无效或可清理由 Agent 结合仓库语义判断。

用户要求改善长期结构、难理解/难测试的模块时读取[架构摩擦体检](references/architecture-audit.md)，先交有证据的候选，再由 joy-shape 收敛选中项；报告的视觉与图表仍交专业能力，不把扫描等同实现授权。

治理聚焦四类结果：

- 常驻入口保持为可靠路由，项目细则只有一个权威来源，旧快照、死链和与代码冲突的描述有明确处置建议；
- 快速局部检查与高耗时全量/端到端/打包门禁分层，确认测试确实被项目或 CI 执行，不把孤儿候选直接当作可删除文件；
- 反复出现且能静态判定的硬规则优先落成项目自己的测试或检查，已有自动门禁后精简重复文字提醒；
- Git 卫生体检发现需要整理的分支或 worktree 后，交给 `joy-git` 产出任务看板与安全处置结果；本模块不另建台账或 worktree 清理规则。

体检输出证据、影响、优先级和建议的最小动作；修改文档、测试、检查脚本或 Git 对象前，遵循用户授权和项目规则。删除含未合入提交或未提交改动的分支/worktree、改写历史、批量删除等高影响动作必须先证明恢复路径和遗漏风险，不能由治理扫描自动执行。

具体测试的保护价值、断言/mock、失败敏感性与保留/改写/删除建议交给 joy-test，本模块保留仓库级测试入口、CI 和快慢门禁的卫生体检。测试数量、覆盖率或一次重跑成功不能代替这些保护证据。

单个顽固缺陷交给 `joy-debug`，具体产品改动交给 `joy-build`，Git 交付与已确认的隔离清理由 `joy-git` 收尾。共享交接标准见套件契约（按技能名发现 `joy-stack`，再从其实际目录读取 `references/stack-contract.md`）。
